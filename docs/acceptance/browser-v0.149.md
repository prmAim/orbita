# Браузерная проверка сохранённого набора v0.149

`frontend/tests/stand-acceptance.mjs` проверяет настоящий интерфейс и его обычные
HTTP-чтения на `http://127.0.0.1:8086/`. Подмена API, replay ответов и прямые
запросы к БД не используются. Нужны Node.js и установленный `agent-browser`.
Новых npm-зависимостей нет.

Сначала выполнить штатный Generate нужного набора по
[операционной инструкции](../operations/local-application.md), открыть именованную
сессию и войти в ней обычным интерфейсом. Пароль вводится отдельно; runner
не читает пароль, cookies, auth-файлы или browser storage и не выполняет вход.

```powershell
agent-browser --session orbita-v149-Standard open http://127.0.0.1:8086/
# Войти в открытой сессии обычным интерфейсом владельца.
node frontend/tests/stand-acceptance.mjs --session orbita-v149-Standard --scenario Standard > .scratch/ui149/stand-Standard.json
```

После штатного Remove/Generate Large и отдельного входа:

```powershell
node frontend/tests/stand-acceptance.mjs --session orbita-v149-Large --scenario Large > .scratch/ui149/stand-Large.json
```

В Windows runner по умолчанию использует native CLI из стандартной глобальной
npm-установки в `%APPDATA%/npm/node_modules/agent-browser/bin/`. При другом месте
установки передать `--cli <полный-путь-к-native-exe>`. Он запускается без shell;
JavaScript передаётся документированной командой `--json eval -b`.

Runner меняет только навигацию, поиск, фильтры, страницы, раскрытие и размер окна.
Кнопки паузы/возобновления, запуска/остановки, допуска, повторов Telegram и выхода
не нажимаются. Именованная сессия остаётся открытой; исходный размер окна
восстанавливается. Поиск и раскрытия после проверки могут отличаться от исходных.
Прогресс идёт в stderr, итоговый JSON — в stdout. Успех: код выхода0 и
`success:true`. При ошибке — код1; прежний файл отчёта не является доказательством
нового успешного прогона. Не публиковать локальные данные сессии или отчёты реальных счетов.

Ожидания закреплены независимо автором сквозного сценария, а не вычисляются
runner из текущего HTTP-ответа:

| Проверка | Standard | Large |
| --- | --- | --- |
| Текущие бумаги |15|15|
| SBER: повторение / ручные / брокер, лоты |2 /4 /6|2 /4 /6|
| Средняя заявки последней ручной продажи SBER / последнее исполнение |107 /112 RUB|107 /112 RUB|
| Активные заявки: Орбита / ручная / неизвестная |2 /1 /1|2 /1 /1|
| Операции |33|158|
| RUB: всего / доступно / заблокировано |954450 /954350 /100|954450 /954350 /100|
| USD: всего / доступно / заблокировано |5 /4 /1|5 /4 /1|

Проверяются семь вкладок, единственная основная цена исполнения и отсутствие
цены в деньгах, происхождение/неопределённость заявок и отсутствие внешних
торговых кнопок, глобальные поиск/фильтр и сортировка по времени, все страницы
25/50/100 со стабильными ID без потерь/дублей. Точная ручная сделка открывается
вне прежнего периода, с собственной ценой112 и средней той же заявки107;
проверяются раскрытие, видимость, фокус, Back и полный журнал паузы. Reload
должен сохранить поиск, сортировку, вторую страницу, раскрытие, scroll и focus.
При390px проверяются подписанные карточки,200%текста, отсутствие горизонтального
выхода и клавиатурный фокус.

Офлайн-стенд вправе показывать честно устаревшие данные и ограниченную полноту
истории; runner не подменяет их свежими и не требует ложного `FRESH`.
Это воспроизводимая браузерная часть #33, а не вся матрица UI-A01–UI-A13:
SQL/SDK-аудит генератора, точечный Remove, сетевой профиль, повторная доставка,
отсутствие торговых эффектов в имитаторе и независимое ревью фиксируются отдельно.
Успешный прогон не доказывает живой брокер, полноту его реальной истории,
настоящий Telegram, USB или торговую приёмку.

При создании артефакта выполнены только Node syntax check и проверка JSON-envelope
установленного CLI на отдельной пустой вкладке. Реальный Standard/Large прогон
после Generate выполняет владелец стенда; до сохранённого успешного отчёта он
считается NOT_RUN.
