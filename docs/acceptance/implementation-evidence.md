# Доказательства локальной реализации

Спецификация — [v0.147](https://github.com/prmAim/orbita/issues/10).
Полный индекс сценариев находится в [матрице](scenarios-v0.147.md).
Документ отличает автоматические проверки, испытания локального развёртывания
и ещё не выполненную живую приёмку. Успех имитатора не подтверждает свойства
реального брокера или компьютера владельца.

## Воспроизводимые проверки

Из `frontend/`: `npm ci`, `npm run typecheck`, `npm run build`.
Из `backend/`: `./mvnw --batch-mode --no-transfer-progress spotless:check verify`.
В Windows используется `mvnw.cmd`. Нужны Java 25 и Docker с Linux containers.
Интеграционные тесты запускает Maven Failsafe; команда `test` их не заменяет.
Проверка прежних Python-инструментов из корня:
`uv run --offline --no-sync python -m unittest discover -s tests -v`.

Границы подтверждены владельцем: расчёт и журнал, команды управления,
SDK через TLS-имитатор, приложение с настоящим PostgreSQL, HTTP и Telegram
через тестовые клиенты. Тестовые контейнеры и синтетические пароли изолированы
от рабочих счетов и сервисов.

## Локальные испытания развёртывания

Промежуточная сборка 2026-11-15 прошла сборку Docker и запуск приложения.
Браузер Chrome for Testing 157.0.8103.78 подтвердил вход, сохранение сессии
при обновлении страницы и открытии другой вкладки, явный выход сразу из
двух вкладок. Сброс пароля из консоли закрыл открытую страницу журнала до
ввода нового пароля. Старый пароль перестал действовать, новый позволил
войти, журнал и режим сохранились. Это проверка R36 с синтетическим паролем.

Приложение создало архив PostgreSQL, восстановило его в отдельную проверочную
БД, сравнило содержимое и перенесло в том, имитирующий USB. Независимо
проверенные SHA-256 локального и перенесённого файлов совпали:
`cfb82f2f560f44f3496c5b8ced492805ad4a534778746ce9371e9c345c9a728c`.
Проверочная БД после проверки удалена. Физическая флешка не участвовала.

Первый прогон выявил ошибку инициализации роли БД. После исправления новая
БД независимо проверена: прикладная роль `orbita` имеет CREATEDB для проверки
архивов, но не SUPERUSER и не CREATEROLE. Bootstrap-роль отделена и не
передаётся приложению. Первая копия сама по себе не доказывает работу
резервирования с ограниченной ролью.

На следующем стенде восстановленное приложение уже с ограниченной ролью
успешно создало, проверило и перенесло новую копию: проверка завершена
2026-11-15 в 17:18:51 UTC. Состояние `TRANSFERRED`, ошибка отсутствует.
SHA-256 обоих файлов:
`d80cdadeb2af4005931167c91e0b5ba16fe38067aa411d7ccdb6f66ded796ec1`.
Проверочных БД `orbita_verify_*` после выполнения не осталось.

Штатный `restore.ps1` восстановил старый архив в новый изолированный проект.
Наблюдались режим `RESTORED`, отсутствие допуска и границы автоотправки,
непройденная сверка, заблокированный доступ прежним паролем и отсутствие
активных сообщений Telegram из копии. Последующие миграции применились
без изменения уже применённых SQL-файлов. Это проверка восстановления
промежуточной сборки; она не заменяет итоговую проверку версии приложения.

## Оставшаяся приёмка

- Доступ к активному счёту подписчика, полнота истории и связь исполнения
  с исходной заявкой, банковские резервы, тариф, комиссия и маржинальный режим.
- Доверие часам конкретного ПК, погрешность и непрерывность после сна/паузы
  виртуальной машины. Потребитель доказательства времени не заменяет
  квалификацию сборщика и платформы.
- Естественные покупка и продажа, независимая теневая сверка и отдельный
  разовый допуск владельца к первой реальной заявке. Живые заявки не отправлялись.
- Реальные Telegram и USB, перезагрузка Windows и установленный автозапуск,
  отказ питания/процесса и срок полного восстановления. Автозапуск не установлен.
- Перенос на выбранный сервер после успешной приёмки на ПК.

Неподтверждённые исходные данные закрывают соответствующий торговый доступ.
Они не объявляются нулевой комиссией, свободными средствами или точными часами.
Полная промышленная эксплуатация пока не принята.
