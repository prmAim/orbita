# Вопросы владельцу T-Invest API: отказ заявки, остановка торгов и нехватка бумаг

**Дата:** 2026-11-17. **Статус:** локальный проект обращения, не отправлен.

**Цель:** установить документированные признаки, позволяющие отличить окончательный
отказ без исполнения от неизвестного результата, и определить применимость причин
остановки торгов и нехватки собственных бумаг.

**От:** разработчика приложения Orbita, использующего T-Invest API.
**Кому:** технической поддержке T-Invest API; при необходимости — владельцу
контракта OrdersService / OrdersStreamService.
**Как будут использованы ответы:** для уточнения спецификации обработки заявок
и решения, можно ли подключить соответствующие причины в адаптере. До получения
достаточных гарантий эти пути остаются отключёнными. Сам ответ не запускает
торговую проверку.

## Контекст

Приложение отправляет лимитные BUY/SELL по собственным средствам и бумагам через
официальный Java SDK Core/Contract 1.51; в PostOrderRequest передаёт неизменяемый
клиентский UUID и `confirm_margin_trade=false`. При потерянном ответе оно сохраняет
резерв и сверяет результат через GetOrderState по счёту и исходному UUID с
`ORDER_ID_TYPE_REQUEST`, без повторного PostOrder. Для окончательного ресурсного
отказа без исполнения требуется окончательно пропустить объём без уменьшенной
повторной заявки. Для отказа из-за остановки торгов предусмотрено отдельное
ограниченное правило повтора, которое нельзя включать без доказательства причины
и отсутствия исполнения. Мы исследовали документацию и SDK, но не нашли достаточных
гарантий для всех этих случаев; просим уточнить контракт производственного API.

## Как ответить

Желаемый срок ответа не установлен. Ориентир для первичного заполнения — 20–30 минут;
если необходима проверка у владельца сервиса, достаточно указать это в ответе.
Можно сначала ответить на раздел об остановке торгов, остальные ответы прислать позже.

Под каждым вопросом оставлено место для ответа. «Не гарантируется», «такого признака
нет» и «нужна дополнительная проверка» полезны: просим не заменять их предположением.
Для каждой гарантии укажите ссылку на актуальный контракт либо прослеживаемое
письменное разъяснение и область действия. Различайте production и sandbox,
серверный API и доступность поля в Java SDK 1.51. Если ответ зависит от инструмента,
площадки или типа счёта, обозначьте границы применимости. Пример обезличенного
ответа полезен как дополнение, но нужен именно контракт, а не только единичный пример.

Для ответов не требуются реальные номера счетов, токены или торговые операции.
