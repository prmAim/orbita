# Общий каркас панели владельца

Каркас остаётся на TypeScript и стандартном DOM без нового frontend-фреймворка.
`frontend/build.mjs` переносит все скомпилированные JS-модули в статические ресурсы
сервера. Для загрузки страницы входа открыты только явно перечисленные файлы;
чтение данных и команды по-прежнему требуют сессию владельца.

## Маршруты и контекст

`OwnerNavigation` из `frontend/src/navigation.ts` использует hash-маршруты:

| Раздел | Маршрут |
| --- | --- |
| Активы | `#assets` |
| Инструменты, активные заявки | `#orders` |
| Операции | `#operations` |
| Журнал | `#journal` |
| Уведомления | `#notifications` |
| Управление | `#control` |
| Копии | `#backup` |

Параметры `instrument`, `operation`, `order`, `fill`, `journal` содержат точные
непрозрачные идентификаторы. `routeHref` кодирует их через `URLSearchParams`;
`readRoute` возвращает исходные строки. Например, ссылка на исполнение содержит
`#operations?fill=...`; разрешение ссылки выполняется отдельным точным HTTP-чтением,
независимым от страницы и фильтров списка. Индекс строки не является идентификатором.

Нативная история браузера обеспечивает переход назад. Навигация хранит фокус
по стабильному `id` и прокрутку отдельно для каждого полного маршрута в
`sessionStorage`. Экран вызывает `navigation.restore()` **после** завершения
асинхронной загрузки и рендера назначения: ранний вызов может восстановить
прокрутку до появления содержимого. Восстановление выполняется однократно для
каждого перехода. Хранилище не содержит торговых фактов или пароля.
Завершение чтения прежнего раздела не восстанавливает контекст нового:
поколение маршрута связывает загрузку с назначением, а пропущенная во время
чтения загрузка текущего раздела выполняется сразу после его завершения.

## Коллекции и точные числа

`CollectionView<T>` из `frontend/src/collection.ts` принимает колонки, стабильный
ключ строки, применимые фильтры и функцию HTTP-чтения `load`. Поиск отправляется
как `q`; `page` начинается с нуля, `size` равен 25, 50 или 100. Сервер применяет
поиск, фильтры и устойчивую сортировку ко всему доступному набору, возвращая
`items`, `total`, `page`, `size`, `freshness`. Компонент не сортирует и не фильтрует
локальную страницу вместо полного набора.

Поиск, фильтры, размер страницы и сортировка сбрасывают страницу на первую;
периодическое обновление её сохраняет. Если прежняя страница стала пустой,
панель сообщает об этом и оставляет переход на предыдущую страницу.
Состояние запроса и раскрытые `details[data-expansion]` сохраняются в
`sessionStorage` по уникальному `id` коллекции. Раскрытия относятся к стабильным
идентификаторам, включая записи временно отсутствующей страницы.

Функции `decimal` и `executionPrice` отображают исходные десятичные строки без
преобразования в `Number` и локального усреднения. `Price.status` поддерживает
`CONFIRMED`, `NO_EXECUTIONS`, `UNCONFIRMED`. Неподтверждённая цена сопровождается
причиной; отсутствие исполнений не заменяется нулём. Экран добавляет ровно одну
основную колонку «Цена исполнения», отдельно от согласованной лимитной цены.

Коллекция различает загрузку (`aria-busy`), пустой результат, ошибку чтения и
устаревшие данные с временем последнего успешного чтения в МСК. Ошибка обновления
сохраняет ранее полученные строки и явно сообщает об их состоянии. Запоздалый
ответ предыдущего запроса не заменяет результат нового выбора.
При ошибке обновления также сохраняется время последнего успешного чтения
показанных строк в МСК; при его отсутствии указано, что успешного чтения не было.

На широком экране используются таблицы; до 760 px строки становятся вертикальными
карточками с подписями полей. Сортировка доступна кнопками с `aria-sort`,
пагинация имеет подписи. Экран должен использовать стабильные ключи и явные
`id` для точных целей фокуса; при отсутствии собственного `id` компонент назначает
его интерактивным элементам из ключа строки и колонки.

## Экраны счёта

`assets.ts`, `orders.ts`, `operations.ts` подключают общую коллекцию к защищённым
GET модели счёта. `account-ui.ts` хранит общие типы DTO, русские подписи, перевод
времени в МСК и отображение исходных точных числовых строк. Денежные средства
показываются отдельно по валютам; общий статус полноты валют не подменяет статус
конкретной валюты. Статусы заявки отличаются от состояния инструмента.

Период операций задан полями `datetime-local` в МСК. Перед HTTP-чтением значения
преобразуются в UTC с явным смещением `+03:00`, независимо от локальной зоны
браузера. Основная таблица не создаёт исходное исполнение или коэффициент для
внешней заявки. Раскрытие загружает связанные заявки по точным ID; уникальные
исполнения группы отображаются один раз отдельным списком, с собственной ценой
и комиссией либо её неподтверждённым состоянием. Сортировка `lots` в операциях
относится к рассчитанному объёму; сортировка неподдерживаемого исходного объёма
не предлагается.

Закрытие доступа очищает DOM и результаты всех трёх коллекций. Поколение доступа
проверяется до обработки HTTP-ответа и после чтения тела: ответ прежней сессии
не попадает в новую сессию. Раскрытие также проверяет поколение и существование
своего узла после асинхронного чтения. Набор публичных модулей явно перечислен
в security allowlist; данные в статических файлах не встраиваются.

Точное разрешение ссылок с восстановлением связанных групп и интеграционная
приёмка всей цепочки относятся к следующим задачам. Каркас не создаёт
демонстрационных данных и не выполняет торговых действий при навигации.
