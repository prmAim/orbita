# Чтение счёта повторения для v0.149 (#26)

`BrokerGateway` предоставляет отдельные методы чтения `readHoldings`,
`readOrders(retainedBrokerOrderIds)`, `readOrderHistory(from, through, retainedIds)`,
`readExecutions(from, through)` и `observeCash(sink)`. Они не вызывают торговые
методы, не создают намерения и не запускают повторение исторических сделок.
Существующие расчёты, квалификация ресурсов и торговый обработчик не меняются.
Проверка использует официальный SDK 1.51 и локальный TLS gRPC-имитатор.

## Контракт достоверности

`AccountRead.Snapshot` содержит элементы, время начала чтения и получения,
признак полноты набора и причины ограничений. Это независимые банковские
наблюдения, а не атомарная фотография всех сервисов. `null` означает отсутствие
подтверждения; ноль допускается только как явное значение API. Полнота набора
не означает подтверждение каждого необязательного поля.

Потребитель обязан сохранять последний успешный факт и его время. Ошибка,
частичный ответ и пропуск строки не удаляют сохранённую позицию, заявку или
валюту. Известные активные/неопределённые заявки передаются в `retainedIds` и
читаются независимо по банковскому ID: только подтверждённый конечный статус
разрешает исключить заявку из активных. Результат чтения не даёт разрешения
отменять ручную или неизвестную заявку.

`Origin.UNKNOWN` — честный банковский результат: SDK не подтверждает источник
«ручная/Орбита». Постоянная модель может установить `ORBITA` по точному совпадению
банковского `orderRequestId` с зарегистрированным намерением. Отсутствие этой
связи недостаточно для `MANUAL`. Подтверждённая ручная классификация возможна
только по отдельным долговечным доказательствам сверки; нельзя угадывать связь
исполнений разных API по времени, цене или объёму.

## Источники полей

| Поле | SDK и семантика | Ограничение |
| --- | --- | --- |
| Бумага, остаток брокера | `GetPortfolio.positions.instrumentUid/ticker/quantity`, количество в штуках | Не валютные позиции, ненулевые; состав портфеля не разделяет происхождение |
| Лоты, название | `GetInstrumentBy.uid/lot/name/ticker`; `quantity / lot` | UID обязан совпасть; `quantityLots`, если задан, должен совпасть с пересчётом. Неподтверждённый размер лота даёт неизвестные лоты |
| Деньги, исходная сумма | `GetPositions.money`, отдельное `reportedMoney` по валюте | Документ не устанавливает свободная это сумма или общая; не прибавляем/не вычитаем blocked и не выдаём её за всего/доступно |
| Заблокированные деньги | `GetPositions.blocked`, по валюте | Отсутствующая валюта не заменяется нулём; гарантийное обеспечение фьючерсов не входит |
| Доступно/заблокировано/всего | `PositionsStream.position.money.availableValue/blockedValue`; всего = их сумма для одной валюты одного сообщения | Обе суммы должны присутствовать с совпадающей валютой. `bankAt` = `PositionData.date`, `receivedAt` = местное получение; это обновление валют, не полный список счёта |
| Активные заявки | `GetOrders` без фильтров; одна строка на `orderId` | У метода нет пагинации; при 100 строках полнота не подтверждена. Повторные ID объединяются, конфликтующие ответы отмечаются |
| История заявок | `GetOrders.advancedFilters` со всеми статусами; окна не длиннее часа | Только документированная история текущего дня. Консервативная нижняя граница — UTC-полночь текущего дня; более ранний запрос явно неполон. При 100 строках окно делится до 1 секунды/12 уровней, затем остаётся явный пробел |
| Ранее сохранённая заявка | `GetOrderState(accountId, orderId, ORDER_ID_TYPE_EXCHANGE, PRICE_TYPE_CURRENCY)` | Читается по банковскому ID, включая внешнюю заявку; доступность старого ID реального счёта не доказана |
| Направление, объёмы, статус, тип | `OrderState.direction/lotsRequested/lotsExecuted/executionReportStatus/orderType` | Объёмы — лоты. Проверяется диапазон исполненного количества. Неизвестный enum остаётся UNKNOWN |
| Дата заявки | `OrderState.orderDate` | Время создания заявки у брокера; не дата сделки и не время опроса. Отсутствующее поле остаётся неизвестным |
| Лимитная цена | `GetOrderState.initialSecurityPrice`, только LIMIT, запрос CURRENCY | Для рыночной/неподтверждённой заявки не применяется/не подтверждено; банковские средние и котировки не используются |
| Фактическое исполнение заявки | `GetOrderState.stages.tradeId/quantity/price/executionTime` | Количество — лоты; цена — MoneyValue в валюте за единицу инструмента при CURRENCY. Ключ хранения: счёт + заявка + tradeId |
| Исторические фактические исполнения | `GetOperationsByCursor.items.tradesInfo`, все страницы и суточные окна через существующий `mirrorHistory` | trade.quantity — штуки, пересчёт в лоты по metadata. Время — trade.date. Дедупликация в пределах account/trade; конфликт даёт пробел. `brokerOrderId=null`: operation ID не считается доказанной связью с orderId |
| Комиссия отдельного исполнения | Нет подтверждённого источника в OrderStage/OperationItemTrade | `commission=null`. Комиссия операции/заявки не распределяется между сделками произвольно |

`observeCash` использует отдельную подписку SDK. После разрыва сообщает пробел
и переподключается; новые валютные строки применяются как upsert по валюте и
банковскому времени, отсутствующие не удаляются. `initialPositions` не
превращает неоднозначный `GetPositions.money` в свободные деньги. Все обновления
имеют `complete=false`, поскольку не подтверждают полную инвентаризацию валют.
Владелец подписки обязан закрыть её при остановке; ошибка сохранения callback
закрывает подписку и не маскируется банковской ошибкой. Свежесть проверяется
потребителем по банковскому и местному времени; само открытое соединение не
подтверждает актуальность суммы.

## Цена исполнения R140

Одинаковые stages с одинаковым tradeId учитываются один раз. Противоречащие
дубликаты, отсутствующие цена/валюта/время/количество, несовпадение суммы
уникальных quantities с `lotsExecuted`, ошибка detail и смешанные валюты
исключают подтверждённую среднюю. Суммы и произведения сохраняют десятичную
точность SDK; только конечное деление использует DECIMAL128. Веса — уникальные
фактически исполненные лоты. Комиссия не включается.

Подтверждённые 2×100 и 3×110 дают 106; ноль исполненных лотов даёт отсутствие
цены при `fillsComplete=true` («Нет исполнений»), а не нулевую цену.
`executedOrderPrice`, `averagePositionPrice`, начальный лимит и текущая котировка
не служат заменой. Привязка истории операций к заявке и полнота всей
исполненной части из одной выборки операций не выводятся. Сохраняемые стадии
заявки и операции разных API нельзя складывать без подтверждённого общего ID:
официальная документация предупреждает о различии trade ID между сервисами и
изменении ID операций. Для средней заявки каноничны её `GetOrderState.stages`.

## Проверка и пределы

`AccountReadTest` проверяет настоящий SDK через локальный TLS: несколько заявок
одной бумаги, повторное чтение, дубликаты stages и взвешенную цену, недоступный
detail, несколько валют, честную неопределённость GetPositions, ограниченную
историю/деление окна при cap, денежный stream и переподключение. Счётчик
PostOrder/CancelOrder/ReplaceOrder остаётся нулевым. Регрессия существующего
`TInvestBrokerGatewayTest` проверяется вместе с новым набором.

Живой брокер, доступ реального счёта к старым заявкам/всем валютам и полная
историческая восстановимость — NOT_RUN. Постоянная модель, управление её
жизненным циклом и HTTP/UI принадлежат следующим задачам #27–33.
