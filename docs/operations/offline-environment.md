# Автономное окружение Orbita: Windows x64 / Python 3.13.18

Цель: хранить установочные файлы независимо от кэша uv и восстанавливать
окружение без доступа к PyPI. Реальные запросы к OpenAI требуют интернета.
Режим `offline` не использует сеть; `local` использует только локальный Langfuse.

## Что сохраняется

Локальный каталог `.offline/windows-x64-cp313/` содержит:

- `wheels/`: wheels всех применимых к этому компьютеру зависимостей из `uv.lock`,
  включая инструменты разработки и отдельно закреплённые сборочные зависимости;
- `requirements.txt`: точные версии и SHA-256 сохранённых wheels;
- `uv.exe`: используемую версию менеджера окружения;
- `python/`: копию установленного standalone Python 3.13.18 с pip;
- `manifest.json`: контрольные суммы файлов и привязку к конфигурации проекта.

Проверенный backend закреплён как `hatchling==1.33.0`. Его зависимости, включая
`editables==0.6` для установки исходников в режиме разработки, закреплены с SHA-256
в `tools/build-requirements.lock`. Подготовка использует этот файл из Git
без обновления версий сборочных пакетов.
Runtime-зависимости по-прежнему берутся из `uv.lock`.

Это набор для конкретной Windows x64 и версии Python, не универсальный архив
для Linux/macOS. Код Orbita берётся из репозитория. `.env`, ключи, базы и
Docker-образы в набор не входят. Бинарный каталог исключён из Git; скопируйте
готовый набор вместе с исходниками на резервный носитель. Сам GitHub его не хранит.

## Однократная подготовка с доступом к интернету

Из корня Orbita, пока текущее окружение работает:

```powershell
uv run --no-sync python tools/offline_env.py prepare
```

Нужен доступ к `pypi.org` и `files.pythonhosted.org`. Скрипт не меняет сетевые
настройки и не обновляет рабочую `.venv`. При прерывании загрузки повторите
команду: совпадающий незавершённый набор можно продолжить. Успешный набор не
перезаписывается — для следующего используйте `--bundle` с новым каталогом.
Если uv не найден в PATH, передайте `--uv` с полным путём к `uv.exe`.

Набор готов только после появления `manifest.json` и успешной проверки.
Наличие отдельных скачанных файлов не означает готовности к восстановлению.

## Проверка набора и восстановление без интернета

Команды используют Python и uv из набора, не требуют глобальной установки uv:

```powershell
.\.offline\windows-x64-cp313\python\python.exe tools/offline_env.py verify
.\.offline\windows-x64-cp313\python\python.exe tools/offline_env.py restore --target .scratch/offline-acceptance
.\.scratch\offline-acceptance\Scripts\python.exe -m unittest discover -s tests -v
```

Для каждого восстановления выберите новый каталог: существующее окружение
скрипт не удаляет и не перезаписывает. По умолчанию цель — `.venv`, но только
если такого каталога ещё нет. При восстановлении рабочей среды существующую
`.venv` сначала сохраните отдельно, убедившись, что никакие процессы её не используют.

Восстановление проверяет SHA-256, запрещает сетевые загрузки uv, использует
только локальный каталог wheels и пустой временный кэш. Сначала устанавливает
закреплённые зависимости с проверкой hashes, затем собирает editable Orbita
уже установленным локальным backend. В конце проверяет зависимости и запускает
`orbita-check` в режиме без сети. Автоматически тестировать OpenAI оно не будет.

## Обычная работа

После установки или восстановления:

```powershell
uv run --no-sync orbita-check
uv run --no-sync orbita-check --mode local
```

Для `local` нужен запущенный Docker Desktop и сохранённые образы/тома Langfuse.
После изменения зависимостей подготовьте и проверьте новый автономный набор.
Старый набор остаётся пригодным для соответствующей ему конфигурации проекта;
несовпадение `pyproject.toml`/lockfile при восстановлении намеренно вызывает отказ.
