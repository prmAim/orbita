# Проверка исполнения на счёте автоследования

Из корня Orbita в PowerShell с установленным окружением выполните

```powershell
.\.venv\Scripts\python.exe -m orbita.execution_probe --known-history
```

По умолчанию утилита использует синтетический счёт и имитатор HTTP внутри
процесса. Ключи, файл `.env`, Docker и сеть для этого прогона не нужны.
Ключ `--known-history` включает также сверку ранее состоявшейся сделки.
Результат `passed synthetic` и код выхода 0 означают успешный прогон имитации.

## После подключения стратегии

Для согласованного живого прогона на ПК нужен токен с правами чтения
и идентификатор именно подключённого счёта. При наличии уже известной сделки
подготовьте её дату в UTC, тикер и подробности исполнения в приложении
брокера. Запускайте из интерактивной консоли. Токен и идентификатор вводятся
скрыто. Если стратегия ещё не совершила сделку, опустите `--known-history`.

```powershell
.\.venv\Scripts\python.exe -m orbita.execution_probe --live-read-only --known-history
```

1. Утилита проверяет доступность введённого счёта, открытый статус и права
   чтения через `GetAccounts`. При включённом поиске известной сделки читает
   историю за выбранную дату и предлагает сверить исполнения по тикеру.
2. Оставьте процесс запущенным до следующей естественной покупки или продажи
   стратегии. `subscription_confirmed False` означает, что брокер принял
   первую подписку. Отдельная запись `execution_received` означает, что
   получено сообщение с исполнением именно этого счёта. Для проверки берётся
   первое исполнение из сообщения. Ожидание можно прервать через Ctrl+C.
3. Клиент закрывает соединение с потоком и открывает новое. После подтверждения
   второй подписки он дважды читает все страницы одного и того же интервала.
   Интервал начинается за пять минут до исполнения и заканчивается после
   подтверждения второй подписки. При задержке
   появления сделки в истории выполняется до 12 чтений для каждого прохода
   с ожиданием 10 секунд между попытками. Сеть и туннель переключать не нужно.
4. Сверьте показанные в локальной консоли инструмент, направление, время UTC,
   количество **штук** и цену за штуку с исполнением в приложении Т-Банка.
   Введите `ДА` только при совпадении. Протокол фиксирует результат сверки.

Успех живой проверки требует одного однозначного совпадения в каждом полном
чтении и подтверждения владельца. Утилита сравнивает отдельные исполнения
по инструменту, направлению, времени, цене и количеству. Идентификаторы сделок
стрима и истории могут различаться. Повтор страницы с той же записью учитывается
один раз в пределах чтения. Несколько разных исполнений с одинаковыми признаками
дают неопределённый результат. Два прохода подтверждают одно наблюдение.

Каждый запуск сохраняет отдельный JSONL в `.scratch/execution-probe/`. В нём
есть режим, время UTC, этапы, номера страниц, результат и причина остановки.
Токен, идентификаторы, сделка и исходные ответы туда не записываются. При
`incomplete` код выхода равен 1. По последнему успешному этапу видно, удалось
ли подтвердить доступ к счёту, подписку, событие или совпадение в истории.
Отсутствие совпадения относится к проверенному интервалу и данным этого прогона.

Проверка охватывает чтение исполнения. Частичное исполнение и сделка во время
самого разрыва требуют отдельных фактических наблюдений. Проверка капитала и
резервов из дополнения к задаче проводится отдельно.
