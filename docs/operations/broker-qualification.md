# Подключение брокера и профиль квалификации

Обычный Compose-запуск оставляет SDK выключенным. Включение соединения не
подтверждает правильность банковских полей и не разрешает торговлю. Для этого
есть отдельный профиль `orbita.broker.qualification`, который по умолчанию
полностью неподтверждён. Профиль заполняется по результатам согласованной живой
квалификации; тестовые значения не являются такими результатами.

## Локальные файлы и включение SDK

Хранить вне репозитория отдельный каталог, например `C:/OrbitaPrivate`, с
`broker-token.txt`, `broker-qualification.properties` и `broker.compose.yaml`.
Первый файл содержит только токен; приложение читает его при запуске и убирает
внешние пробелы. Не передавать токен в аргументах процесса или чат. Ограничить
доступ к каталогу средствами Windows и разрешить чтение Docker Desktop;
контейнер работает с UID/GID `65534:65534` и должен иметь доступ на чтение.

Локальный `broker.compose.yaml`:

```yaml
services:
  app:
    environment:
      ORBITA_BROKER_ENABLED: "true"
      ORBITA_BROKER_TOKEN_FILE: /run/orbita-private/broker-token.txt
      SPRING_CONFIG_IMPORT: file:/run/orbita-private/broker-qualification.properties
    volumes:
      - type: bind
        source: C:/OrbitaPrivate
        target: /run/orbita-private
        read_only: true
        bind:
          create_host_path: false
```

Путь должен указывать на существующий частный каталог. В `deploy/.env` уже
должны быть заданы разные `ORBITA_SOURCE_ACCOUNT` и `ORBITA_MIRROR_ACCOUNT`.
Команда подключения после отдельного разрешения на реальные API:

```powershell
powershell -File deploy/start.ps1 -ComposeOverride C:/OrbitaPrivate/broker.compose.yaml
```

Это подключает настоящий SDK к банку. Автоматические проверки эту команду с
токеном не выполняют. Отсутствующий обязательный импорт или пустой файл токена
останавливают запуск. Для запуска только без квалифицированных торговых
доказательств файл профиля может содержать
`orbita.broker.qualification.enabled=false`; соединение и квалификация независимы.

## Состав профиля

Все поля ниже относятся к префиксу `orbita.broker.qualification.`. Неизвестное
имя поля, некорректный тип или неполный включённый профиль приводят к ошибке
запуска. Частично подтверждённые возможности не дополняются предположениями.

| Поле | Требование |
| --- | --- |
| `enabled` | Явное включение операторского профиля; по умолчанию `false` |
| `evidence-reference` | Непустая ссылка на фактический протокол квалификации, до 2000 символов, без управляющих символов |
| `valid-until` | Конечный UTC `Instant` из протокола; срок по умолчанию отсутствует |
| `capital-account-ids` | Через запятую ровно два настроенных счёта, без посторонних счетов |
| `mirror-account-id` | Точное совпадение с настроенным счётом повторения |
| `capital-composition-confirmed` | Подтверждён смысл общей RUB-оценки обоих счетов; по умолчанию `false` |
| `instrument-ids` | Явный список UID с подтверждёнными единицами цены, лота и ресурсов; обязателен для ресурсов и фактической комиссии |
| `reserve-currency` | Трёхбуквенный код подтверждённой валюты расчётов и резерва; обязателен для ресурсов и фактической комиссии |
| `own-resource-interpretation-confirmed` | Подтверждены собственные деньги и доступность расчётов; по умолчанию `false` |
| `commission-interpretation-confirmed` | Подтверждена трактовка предварительной комиссии по разности полной и исходной стоимости; по умолчанию `false` |
| `margin-disabled-confirmed` | Подтверждено отключение маржи на счёте; по умолчанию `false` |
| `additional-commission-reserve` | Явный неотрицательный дополнительный резерв в указанной валюте; нулевого значения по умолчанию нет; не более 28 знаков после точки и 36 до точки |
| `own-money-basis` | Подтверждённая трактовка собственных средств, описанная ниже; по умолчанию `UNQUALIFIED` |
| `actual-commission-total-confirmed` | Независимо подтверждена полнота фактической комиссии терминальной заявки; по умолчанию `false` |

При включении любого из трёх признаков ресурсов обязательны область
инструментов/валюты, резерв и квалифицированная трактовка собственных денег.
Для профиля только капитала эти поля не нужны: все признаки ресурсов и
фактической комиссии остаются `false`. Нельзя включать признаки заранее ради
снятия диагностической блокировки.

`GROSS_BEFORE_PROGRAM_RESERVES` допустим только при доказанном значении
собственных денег до программных резервов: приложение вычитает свои резервы
один раз. `NET_REQUIRES_EXACT_BANK_RESERVE_EVIDENCE` обозначает необходимость
точного банковского покрытия каждого резерва. Текущий SDK-потребитель такого
покрытия не достраивает, поэтому этот вариант сохраняет блокировку ресурсов.
Нельзя выбирать `GROSS_BEFORE_PROGRAM_RESERVES`, если банк фактически возвращает
уже уменьшенную сумму. Профиль не заменяет текущие ответы API и их проверки.

Помимо этого поля профиля действует отдельная глобальная настройка
`orbita.margin-disabled-confirmed` (по умолчанию `false`). Контроль приложения
требует её явного подтверждения для новых отправок; она не подтверждает банковскую
семантику ресурсов и не заменяет одноимённое поле профиля. Оба подтверждения
опираются на фактическую проверку отключённой маржи.

Шаблон для первоначального профиля только подтверждённого капитала (угловые
скобки заменяются фактическими данными; это не готовая квалификация):

```properties
orbita.broker.qualification.enabled=true
orbita.broker.qualification.capital-composition-confirmed=true
orbita.broker.qualification.capital-account-ids=<SOURCE_ACCOUNT>,<MIRROR_ACCOUNT>
orbita.broker.qualification.mirror-account-id=<MIRROR_ACCOUNT>
orbita.broker.qualification.evidence-reference=<REFERENCE_TO_ACTUAL_PROTOCOL>
orbita.broker.qualification.valid-until=<ACTUAL_EXPIRY_UTC_INSTANT>
```

Настройки неизменяемы в пределах процесса. После изменения профиля нужно
пересоздать только приложение с теми же env/override/project, например для
стандартного проекта и `deploy/.env`:

```powershell
docker compose --project-name orbita --project-directory deploy -f deploy/compose.yaml -f C:/OrbitaPrivate/broker.compose.yaml up -d --no-build --no-deps --force-recreate app
```

При истечении срока процесс может продолжать чтение, но профиль больше не
квалифицирует капитал, ресурсы или окончательную комиссию. Чужой счёт, UID или
валюта не входят в область подтверждения. Изменение профиля не выдаёт разовый
допуск, не включает автоматическую отправку и не устраняет неизвестный исход
предыдущей заявки.

Время подключается отдельно по [протоколу часов](qualified-clock-evidence.md),
рублёвая стоимость валютного допуска — по
[протоколу оценки RUB](qualified-rub-valuation.md). Эти настройки можно включить
в тот же частный импорт, сохранив собственные области и сроки доказательств.
