# Внешнее подтверждение времени

Приложение само не измеряет точность NTP, Windows, WSL2 или Docker. Без
подтверждённого источника `ClockEvidence` отправка новых заявок запрещена.
Свойство `orbita.clock-uncertainty-millis` не является таким доказательством.
Реальная квалификация коллектора и платформы остаётся частью G3/#15.

Для подключения внешнего квалифицированного коллектора задаются:

```properties
orbita.clock-evidence.file=/run/orbita-clock/evidence.properties
orbita.clock-evidence.host-id=<идентификатор квалифицированного хоста>
orbita.clock-evidence.collector-id=<идентификатор квалифицированного коллектора>
```

Файл находится вне репозитория. В контейнер приложения его следует монтировать
только для чтения. Коллектор заменяет файл атомарно. При отсутствии файла,
неполной записи, неверных значениях или несовпадении идентичности доказательство
отклоняется. В режиме сброса пароля потребитель отключён.

## Контекст процесса и формат

Локальный аутентифицированный `GET /api/clock/context` возвращает `sessionId`,
`hostId`, `collectorId`, `localUtc` и `monotonicNanos`. Новый процесс приложения
получает новый случайный `sessionId`. Коллектор должен получить свежий контекст,
независимо установить границы UTC именно для этой точки и учесть погрешность
измерения, доставки и собственной обработки. Простое копирование `localUtc`
в границы UTC не подтверждает точность часов.

Файл UTF-8 содержит ровно следующие поля `ключ=значение`, без повторов:

| Поле | Содержание |
| --- | --- |
| `format` | `orbita-clock-evidence-v1` |
| `sessionId` | UUID из контекста текущего процесса |
| `hostId`, `collectorId` | Идентификаторы, совпадающие с настройкой |
| `reference` | Непустая ссылка на квалификацию источника и метода измерения |
| `sequence` | Неотрицательный, монотонно возрастающий номер наблюдения |
| `sampleMonotonicNanos` | `monotonicNanos` из контекста данного наблюдения |
| `sampleLocalUtc` | Соответствующий `localUtc` в формате `Instant` |
| `earliestUtc`, `latestUtc` | Независимо подтверждённый диапазон UTC для точки наблюдения |
| `validForNanos` | Положительный срок применимости данного наблюдения |
| `maxDriftPpb` | Неотрицательная подтверждённая граница роста ошибки в частях на миллиард |
| `maximumPollingGapNanos` | Положительный квалифицированный предел непрерывности опроса |
| `maximumWallMonotonicSkewNanos` | Положительный квалифицированный предел расхождения календарного и интервального хода |

Значений срока, дрейфа и пределов непрерывности по умолчанию нет. Коллектор
обосновывает их для конкретного окружения. Числа из автоматических тестов
относятся только к имитатору.

## Применение и потеря доверия

Потребитель переносит границы наблюдения на прошедший интервал текущего JVM
`nanoTime` и расширяет обе стороны на квалифицированный дрейф с округлением
наружу. `TimeAuthority` проверяет наибольшее расстояние от показания текущих
календарных часов до обеих границ подтверждённого диапазона UTC.
Чтение файла и разбор предшествуют измерению текущего интервала; задержка
получения календарного показания включается в границы наружу.
Действуют R61/R65: весь возраст исполнения должен лежать в `[0;60]` секунд,
а ошибка часов — не превышать ±0,5 секунды.

Для срока заявки и поиска отсутствующего времени исходного исполнения SDK
фиксирует монотонную отметку получения до обработки и записи уведомлений.
`atReceipt` восстанавливает UTC именно этой отметки из применимого наблюдения,
а не переносит начало срока на завершение чтения файла. Допускается сохранённое
ранее проверенное наблюдение при обновлении файла, если срок и непрерывность
подтверждены. Новое наблюдение, снятое уже после получения, само по себе не
доказывает прошлую точку. После разрыва доверия старые наблюдения очищаются;
недоказанная точка остаётся неизвестной.

Истечение срока, разрыв опроса, расхождение календарного и интервального хода,
некорректный файл или откат номера наблюдения лишают доказательство силы.
Для восстановления требуется наблюдение строго после обнаруженного разрыва
в текущем процессе; изменение содержимого под прежним номером не принимается.
Исправление времени само по себе не снимает остановки, паузы и неизвестные
результаты брокерских действий.

Коллектор обязан отдельно квалифицировать сон хоста, приостановку контейнера
и восстановление виртуальной машины. Локальный потребитель не может доказать
отсутствие одновременного отката памяти процесса, календарных и интервальных
часов и файла. Защиту от этого класса отказа подтверждает внешний источник;
эта реализация не объявляет платформу квалифицированной.

Автоматические проверки `QualifiedClockEvidenceFileTest` наблюдают результат
проверки возраста: корректное доказательство разрешает временной допуск,
просрочка, неверный процесс/хост, отсутствие дрейфа/происхождения, скачок часов
и разрыв непрерывности оставляют отправку заблокированной. Живая проверка
часов, счёта и торговых действий не выполнялась.
