# Подтверждённая рублёвая оценка разового допуска

`RubValuation` проверяет предел допуска в RUB. Он не выполняет валютный обмен
и не заменяет общую банковскую оценку капитала по R09. Для суммы в RUB
используется точное тождественное преобразование. Для другой валюты без
подтверждённого коэффициента возвращается отказ в квалификации, а не нулевая
стоимость. Первая живая попытка по-прежнему ограничена одним RUB-лотом.

## Рабочий путь после квалификации источника

В приложении есть готовый потребитель внешних краткоживущих доказательств.
Подключение не требует изменения Java-кода. Внешний квалифицированный коллектор
получает подтверждённые данные банка либо иного явно согласованного источника,
проверяет их смысл и публикует файл. Приложение проверяет его область,
интервалы и происхождение перед использованием.

Задаются все четыре настройки, без значений по умолчанию:

```properties
orbita.rub-valuation.evidence-directory=/run/orbita/qualified-rates
orbita.rub-valuation.collector-id=<идентификатор квалифицированного коллектора>
orbita.rub-valuation.maximum-evidence-age=<обоснованный положительный Duration не более PT5S>
orbita.rub-valuation.maximum-rate-window=<обоснованный положительный Duration>
```

Предел срока доставки доказательства дополнительно ограничен 5 секундами,
чтобы коэффициент, используемый при проверке стоимости, не обходил окно R59.
Допустимую длительность периода применимости самого коэффициента оператор
задаёт явно по результату квалификации. Необоснованные долгие сроки не
превращают старую цену в подтверждённую оценку.

Каталог находится вне репозитория и монтируется в приложение только для
чтения. Коллектор пишет файл атомарной заменой. В режиме сброса пароля
потребитель и его endpoint отключены. Для валютной оценки нужны достоверные
текущие границы UTC из `TimeAuthority`; настройка пути к файлу не подтверждает
часы и не обходит отдельную квалификацию времени.

## Контекст и файл

Через аутентифицированный локальный интерфейс коллектор запрашивает:

```text
GET /api/valuation/context?instrumentId=<UID>&currency=CNY&purpose=PRE_SEND
GET /api/valuation/context?instrumentId=<UID>&currency=CNY&purpose=FINAL_COST
```

Ответ содержит случайный `sessionId` текущего JVM, фиксированный счёт
повторения, идентификатор коллектора, полную область `scope` и `fileName`.
Имя файла вычисляется из счёта, UID инструмента, валюты расчётов и назначения.
Пользовательский UID не используется как путь. При каждом новом процессе
нужен новый контекст; файл из предыдущего JVM не принимается.

В `evidence-directory/fileName` публикуется UTF-8-файл не более 16 KiB с ровно
следующими непустыми полями `ключ=значение`, без повторов:

| Поле | Требование |
| --- | --- |
| `format` | `orbita-qualified-rub-rate-v1` |
| `sessionId`, `collectorId` | Точное соответствие контексту и настройке |
| `accountId`, `instrumentId`, `currency`, `purpose` | Область контекста; назначение `PRE_SEND` либо `FINAL_COST` |
| `basis` | `QUALIFIED_RUB_COST_PER_SETTLEMENT_UNIT`: подтверждённая стоимость в RUB одной единицы валюты расчётов |
| `qualificationReference` | Ссылка на проверенный источник, трактовку единиц/направления и применимость к стоимости с комиссией |
| `sequence` | Неотрицательный возрастающий номер доказательства данной области |
| `rateNumerator`, `rateDenominator` | Строго положительные целые числа точного отношения RUB/единица валюты расчётов |
| `rateValidFrom`, `rateValidThrough` | UTC-период, для которого коэффициент подтверждён |
| `evidenceAsOf`, `evidenceExpiresAt` | UTC-интервал свежести независимо полученного доказательства |

Указание символа валютной пары или цены из произвольного поля SDK само по
себе не подтверждает направление и единицы. Коллектор обязан доказать именно
RUB за одну единицу валюты расчётов; обратная котировка, размер лота, номинал
и другие множители не угадываются приложением. Поле `basis` обозначает уже
квалифицированный контракт, а не выполняет такую квалификацию автоматически.

## Отправка и окончательный результат

При `PRE_SEND` рублёвой оценке подлежит сумма стоимости всего рассчитанного
объёма по лимиту, предварительной комиссии и дополнительного резерва.
Резерв прибавляется один раз. Предел не уменьшает рассчитанное количество:
если вся сумма не проходит, данный сигнал остаётся теневым.

При `FINAL_COST` используются независимо подтверждённые исполнения и
фактическая комиссия нужных счёта, UUID и валюты. Дополнительный резерв не
является расходом и повторно не прибавляется. Коэффициент должен покрывать
весь интервал исполнений. Свежесть получения доказательства и исторический
период применимости коэффициента различаются: сегодняшний файл может
подтверждать историческую оценку только при наличии соответствующих
независимых данных. Нынешний курс не подставляется за исторический.

Если единого подтверждённого коэффициента на весь запрошенный интервал нет,
этот файл не подходит. Приложение не усредняет несопоставимые котировки и не
расширяет период автоматически.

Обе границы текущего подтверждённого UTC должны лежать внутри интервала
свежести доказательства; весь интервал оценки — внутри периода применимости
коэффициента. Пропущенное поле, чужой счёт/инструмент/валюта/назначение,
просрочка, некорректный коэффициент, повторный номер с изменённым содержимым
либо отсутствие актуального источника времени исключают использование.
После исправления публикуется новое доказательство с большим `sequence`.

Сравнение с пределом производится перекрёстным умножением целых числителей
и знаменателей. Двоичная арифметика и округление вниз не управляют допуском.
`rubCeiling()` даёт консервативную запись для журнала; `within(cap)` — точное
решение. Фактическая интеграция с режимами, разовым допуском и приёмкой
находится в `TradingService` и `AcceptanceService`.

## Проверенное и непроверенное

Автоматические проверки используют синтетические доказательства. Модель
A190: два лота по 100 CNY и комиссия 1 CNY при 12 RUB/CNY дают ровно 2412 RUB;
предел 2412 проходит, 2411 не проходит. Отдельно проверены дополнительный
резерв один раз, фактическая комиссия в окончательном результате, точная
дробь 1/3, истечение срока, чужая область, повтор номера и исторический
интервал. Значение 12 — только модельное число, не настройка приложения.

Настоящие источник коэффициента, трактовка SDK, тариф, счёт, часы и внешнее
получение исторического доказательства требуют явной квалификации перед
живыми действиями. В этой работе котировки, счета и торговые методы
реального брокера не вызывались.
