# Подтверждение своевременной записи коэффициента

Для R51 новые числовые значения сначала сохраняются как непринятый кандидат: действующим остаётся прежний коэффициент, пока успешное подтверждение COMMIT не докажет запись в пятисекундном окне и допустимый интервал получения ответов. Принятие переводит ссылку на уже сохранённые значения; общая блокировка управления охватывает запись кандидата, проверку и принятие, чтобы остановка и приём исходного исполнения не могли вклиниться между ними по R93. Банковские запросы выполняются до этой блокировки.

Проверки только перед COMMIT недостаточно: задержанный COMMIT уже мог бы сохранить действующий коэффициент за пределами окна, а исключение после него не отменяет совершённую запись. Поэтому неподтверждённые кандидаты отклоняются при восстановлении, а границы UTC самой записи и подтверждения сохраняются для R95; интервал, пересекающий 02:00 МСК, не доказывает порядок и отклоняется с сохранением прежнего значения и действующей политики повтора.

Основания: [R51, R93, R95](https://github.com/prmAim/orbita/issues/10), [границы транзакций](../architecture/application.md), PostgreSQL-регрессии `CapitalTimingIT` и `AbandonedCapitalIT`. Это техническое решение реализации; оно не заменяет квалификацию часов компьютера.
